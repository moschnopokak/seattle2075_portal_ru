# Запуск портала «Сиэтл 2075»: пошаговый гайд

После этого гайда портал будет работать по адресу вида `https://portal.example.ru` с замком в браузере. Игроки будут входить через Telegram, а бот будет присылать уведомления и держать закреплённый статус в чате стола.

Сама работа займёт около часа. Ещё от нескольких минут до нескольких часов может уйти на ожидание, пока домен начнёт указывать на сервер.

Гайд идёт по порядку. Шаги 1–3 делаются в браузере и Telegram, шаги 4–9 в консоли сервера.

---

## 0. Как всё связано

```
Игрок ──► https://portal.example.ru ──► VPS
                                         ├─ Caddy: HTTPS и сертификат
                                         └─ app: портал и база SQLite
Telegram ◄──► бот (вход, уведомления, закреп в чате стола)
```

- **Домен** указывает на IP вашего VPS.
- **Caddy** принимает запросы, сам получает и продлевает сертификат HTTPS и передаёт запросы порталу.
- **Портал** (контейнер `app`) хранит всё в одном файле базы `data/portal.db`.
- **Бот** нужен для входа: Telegram подтверждает личность игрока подписью бота. Через бота же идут уведомления.

Всё это запускается двумя контейнерами Docker. Если Docker на сервере не заведётся, есть вариант без него (раздел 15).

---

## 1. Сервер

Подойдёт любой VPS с такими параметрами:

- система **Ubuntu 22.04 или 24.04**;
- 1 ядро, 1 ГБ памяти, 10 ГБ диска (порталу хватит с большим запасом);
- публичный IPv4-адрес;
- доступ по SSH (логин `root` или пользователь с `sudo`).

У некоторых хостеров есть собственный сетевой фильтр в панели управления. Если он есть, откройте в нём входящие порты **22, 80 и 443**.

Запишите IP сервера, дальше он понадобится.

---

## 2. Домен

Вход через Telegram работает только на домене, по голому IP он не запустится. Подойдёт и поддомен уже имеющегося домена, например `portal.вашдомен.ru`.

1. В панели регистратора (или там, где настроен DNS) создайте **A-запись**:
   - имя: `portal` (или `@`, если портал будет на самом домене);
   - значение: IP вашего сервера;
   - TTL: минимальный из доступных.
2. Проверьте с компьютера, что запись заработала:

   ```
   nslookup portal.example.ru
   ```

   В ответе должен появиться IP сервера. Если его нет, подождите и проверьте снова: обновление DNS занимает от минут до нескольких часов.

Пока ждёте, можно делать шаги 3–7. Шаг 8 (запуск) стоит делать, только когда домен уже указывает на сервер, иначе сертификат не выдастся.

## 3. Бот в Telegram

Всё делается в чате с **@BotFather**.

### 3.1. Создать бота

1. Отправьте `/newbot`.
2. Введите отображаемое имя, например `Сиэтл 2075`.
3. Введите имя пользователя бота, оно должно заканчиваться на `bot`, например `seattle2075_portal_bot`.
4. BotFather пришлёт **токен** вида `1234567890:AAH...`. Это пароль от бота: никому его не показывайте и не выкладывайте в общий чат.

Запишите токен и имя бота без `@`.

### 3.2. Привязать домен (обязательно)

1. Отправьте `/setdomain`.
2. Выберите бота.
3. Отправьте домен портала **без** `https://` и без слэша в конце: `portal.example.ru`.

Без этого шага кнопка входа на сайте покажет ошибку «Bot domain invalid».

### 3.3. Кнопка портала внутри Telegram (желательно)

Так портал будет открываться прямо в Telegram, без браузера.

1. Отправьте `/mybots`, выберите бота.
2. **Bot Settings → Menu Button → Configure menu button**.
3. Отправьте адрес `https://portal.example.ru`.
4. Отправьте название кнопки, например `Календарь`.

Теперь в чате с ботом слева от поля ввода будет кнопка «Календарь».

### 3.4. Оформление (по желанию)

`/setuserpic` задаёт аватар, `/setdescription` текст, который человек видит до нажатия «Запустить». Например: «Портал кампании Сиэтл 2075: календарь, планы и уведомления».

## 4. Подготовка сервера

### 4.1. Подключиться

С Windows 10/11 это можно сделать прямо из PowerShell, с Linux и macOS из терминала:

```
ssh root@IP_СЕРВЕРА
```

При первом подключении ответьте `yes` на вопрос об отпечатке ключа.

Дальше команды даны с `sudo`. Если вы вошли как `root`, `sudo` можно не писать, но и вреда от него не будет.

### 4.2. Обновить систему

```bash
sudo apt update && sudo apt upgrade -y
sudo apt install -y unzip nano
```

Если после обновления система попросит перезагрузку, выполните `sudo reboot` и подключитесь заново.

### 4.3. Проверить часы

Вход через Telegram сверяет время подписи, поэтому часы сервера должны идти правильно:

```bash
timedatectl
```

В строке `System clock synchronized` должно быть `yes`. Если там `no`, выполните `sudo timedatectl set-ntp true`.

### 4.4. Включить сетевой экран

Порядок важен: сначала разрешить SSH, потом включать экран. Иначе вы отрежете себе доступ к серверу.

```bash
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
sudo ufw status
```

На вопрос `Proceed with operation` ответьте `y`.

### 4.5. Убедиться, что порты 80 и 443 свободны

На некоторых образах хостеров уже стоит веб-сервер:

```bash
sudo ss -tlnp | grep -E ':80 |:443 '
```

Если вывод пустой, всё в порядке. Если там `apache2` или `nginx`, остановите и отключите то, что нашлось:

```bash
sudo systemctl disable --now apache2    # если занят apache2
sudo systemctl disable --now nginx      # если занят nginx
```

Если вы пойдёте по варианту без Docker (раздел 15), nginx не отключайте: он там нужен.

---

## 5. Установка Docker

Ставим Docker из пакетов Ubuntu:

```bash
sudo apt install -y docker.io docker-compose-v2
sudo systemctl enable --now docker
docker --version
docker compose version
```

Обе последние команды должны вывести версии. Если `docker compose version` пишет, что такой команды нет, проверьте, что пакет `docker-compose-v2` установился без ошибок.

Проверьте, что образы скачиваются:

```bash
sudo docker pull python:3.12-slim
sudo docker pull caddy:2
```

Если оба образа скачались, продолжайте. Если скачивание обрывается с ошибками доступа, перейдите к разделу 15: там запуск без Docker.

## 6. Загрузка проекта на сервер

### 6.1. Скопировать архив

С Windows (PowerShell), из папки, где лежит архив:

```
scp seattle2075-portal.zip root@IP_СЕРВЕРА:/opt/
```

Если удобнее мышкой, подойдёт WinSCP: подключение по SFTP с теми же IP и логином, архив перетаскивается в `/opt`.

### 6.2. Распаковать

На сервере:

```bash
cd /opt
sudo unzip seattle2075-portal.zip
cd /opt/seattle2075-portal
ls -la
```

В списке должны быть `app`, `static`, `config`, `deploy`, `docker-compose.yml`, `Dockerfile`, `.env.example`.

Дальше все команды выполняются из папки `/opt/seattle2075-portal`.

## 7. Настройка

### 7.1. Файл .env

```bash
sudo cp .env.example .env
sudo nano .env
```

Заполните:

| Переменная | Что вписать | Пример |
|---|---|---|
| `DOMAIN` | домен портала без `https://` | `portal.example.ru` |
| `SITE_URL` | полный адрес портала | `https://portal.example.ru` |
| `BOT_TOKEN` | токен из шага 3.1 | `1234567890:AAH...` |
| `BOT_USERNAME` | имя бота без `@` | `seattle2075_portal_bot` |
| `TG_CHAT_ID` | пока оставьте пустым, заполним в шаге 10 | |
| `NOTIFY_DM` | `1`, чтобы бот писал игрокам лично | `1` |
| `SECRET_KEY` | оставьте пустым, ключ создастся сам | |
| `DEV_LOGIN` | на сервере всегда `0` (при заданном `BOT_TOKEN` портал всё равно его игнорирует) | `0` |
| `COOKIE_SECURE` | на сервере всегда `1` | `1` |

Сохранение в nano: `Ctrl+O`, затем `Enter`, выход `Ctrl+X`.

Закройте файл от посторонних глаз:

```bash
sudo chmod 600 .env
```

### 7.2. Список игроков: players.toml

```bash
sudo cp config/players.example.toml config/players.toml
sudo nano config/players.toml
```

Файл состоит из трёх частей.

**Мастер:**

```toml
[gm]
name = "Мастер"
telegram_ids = []
telegram_usernames = []
```

**Игроки и их персонажи.** У Максима два персонажа:

```toml
[[players]]
name = "Максим"
telegram_ids = []
telegram_usernames = []
characters = ["alice", "karu"]
```

Замените заготовки «Игрок Гейта», «Игрок Рига» и остальные на настоящие имена игроков. Коды персонажей в `characters` должны совпадать с `id` в третьей части.

**Персонажи.** Эта часть уже заполнена, `gen` означает имя в родительном падеже («приглашение от Рига»).

**Как указать человека.** Есть два способа, можно сочетать:

- `telegram_ids = [123456789]`: числовой ID. Надёжно, ID никогда не меняется.
- `telegram_usernames = ["maksim"]`: имя пользователя без `@`. Удобно на старте, но человек может его сменить.

Числовых ID пока можно не знать. Оставьте списки пустыми: при первом входе портал покажет каждому его ID, и вы впишете число сюда. Этот файл портал перечитывает сам, перезапускать ничего не нужно.

Правила синтаксиса: текст в кавычках, числа без кавычек, элементы списка через запятую, списки в квадратных скобках.

## 8. Запуск

Перед запуском проверьте, что домен уже указывает на сервер:

```bash
getent hosts portal.example.ru
```

Должен вывестись IP сервера.

### 8.1. Папка для данных

Портал внутри контейнера работает от пользователя с номером 1000. Ему нужна своя папка для базы:

```bash
sudo mkdir -p data
sudo chown 1000:1000 data
```

### 8.2. Сборка и старт

```bash
sudo docker compose up -d --build
```

Первая сборка занимает пару минут. Затем проверьте:

```bash
sudo docker compose ps
```

Оба сервиса, `app` и `caddy`, должны быть в состоянии `running` (или `Up`).

### 8.3. Журналы

```bash
sudo docker compose logs --tail 30 app
```

При нормальном старте там будут строки `База заполнена из config/campaign.json` и `Application startup complete`. Предупреждений про `BOT_TOKEN` и `DEV_LOGIN` быть не должно.

```bash
sudo docker compose logs --tail 30 caddy
```

Здесь должна появиться строка про успешно полученный сертификат (`certificate obtained successfully`). Обычно на это уходит до минуты.

### 8.4. Проверка снаружи

Откройте в браузере `https://portal.example.ru`. Должна открыться страница входа с замком в адресной строке и кнопкой «Войти через Telegram».

## 9. Первый вход и настройка кампании

### 9.1. Войти мастером

1. Нажмите «Войти через Telegram» и подтвердите вход в Telegram.
2. Telegram спросит, разрешить ли боту писать вам. Разрешите: так будут приходить заявки на развитие.
3. Скорее всего, портал ответит «Вашего Telegram нет в списке игроков» и покажет число. Это ваш ID.
4. Впишите его на сервере в раздел мастера:

   ```bash
   sudo nano config/players.toml
   ```

   ```toml
   [gm]
   name = "Мастер"
   telegram_ids = [123456789]
   ```

5. Вернитесь в браузер и нажмите «Проверить ещё раз». Откроется портал с панелью мастера.

### 9.2. Выставить время кампании

Откройте **Панель мастера**:

1. **Перейти к дате**: выберите текущий день кампании и нажмите «Перейти».
2. **Время суток**: утро, день, вечер или ночь.
3. **Свободное время гарантировано до**: день, до которого игроков точно не выдернут на задание. Если гарантий нет, выберите «не гарантировано».

### 9.3. Посмотреть глазами игрока

В шапке, в поле **Вид**, выберите «как видит Элис» (или любого другого персонажа). Так видно ровно то, что откроется игроку. Действия в этом режиме отключены. Вернитесь в режим «Мастер».

## 10. Чат стола и уведомления

### 10.1. Узнать ID чата стола

1. Добавьте бота в групповой чат стола.
2. Сделайте его администратором и включите право **закреплять сообщения** (остальные права можно не давать).
3. Отправьте в группе: `/start@имя_вашего_бота`.
4. Откройте в браузере (подставьте свой токен целиком):

   ```
   https://api.telegram.org/bot<ТОКЕН>/getUpdates
   ```

5. Найдите фрагмент вида `"chat":{"id":-1001234567890,"title":"…"`. Число вместе с минусом и есть ID чата.

Если ответ пустой (`"result":[]`), отправьте в группу ещё одно сообщение с упоминанием бота и обновите страницу.

### 10.2. Прописать его

```bash
sudo nano .env
```

```
TG_CHAT_ID=-1001234567890
```

После правки `.env` контейнер нужно **пересоздать**. Простого перезапуска для этого мало:

```bash
sudo docker compose up -d
```

### 10.3. Проверить

В панели мастера сдвиньте время на день вперёд и сразу обратно. В чате стола появится и закрепится сообщение с датой, этапом и свободным временем. Дальше бот будет редактировать это же сообщение, а не присылать новые.

### 10.4. Личные уведомления

Бот пишет человеку лично, только если тот разрешил: нажал «Запустить» в чате с ботом или согласился при входе на сайт. Приходят:

- приглашение в запись и изменение её даты;
- ответ на ваше приглашение;
- кто-то напросился в вашу запись по «+»;
- решение мастера по развитию;
- новая раздатка;
- общее событие (маска плана мастера), которое касается персонажа;
- мастеру: новая или изменённая заявка на развитие.

Кнопка «Открыть портал» под сообщением открывает портал прямо в Telegram, сразу на нужном разделе и без отдельного входа. В закрепе чата стола кнопка ведёт на сайт обычной ссылкой: в группах Telegram другие кнопки не разрешает.

## 11. Приглашение игроков

Текст, который можно отправить в чат стола:

> Запустили портал кампании: https://portal.example.ru
> Там календарь: какой сейчас день в игре, сколько свободного времени, свои планы, приглашения и обсуждения.
> Вход через Telegram, пароль не нужен. Если после входа портал покажет номер, перешлите его мне.
> Ещё откройте бота @имя_бота и нажмите «Запустить», тогда будут приходить уведомления. С телефона удобнее открывать портал кнопкой «Календарь» в чате с ботом.

Когда игроки пришлют номера, впишите их в `telegram_ids` соответствующих игроков в `config/players.toml`. Им останется нажать «Проверить ещё раз».

Проверьте себя: зайдите в режим «Вид: как видит…» каждого персонажа и убедитесь, что Максим видит переключатель «Играю за» с Элис и Кару.

## 12. Повседневная работа

### Время

Двигается в панели мастера. Закреп в чате стола обновится сам.

### Этапы, регулярные события, таймеры, план мастера и хроника

Всё редактируется в **Панели мастера**. У каждого раздела есть кнопка «Добавить». Любое событие открывается щелчком, в карточке есть кнопки «Изменить» и «Удалить». Удаление срабатывает со второго нажатия, чтобы не удалить что-то случайно. События хроники правятся прямо в разделе «Хроника».

- **Этапы.** Название для игроков и отдельное название для мастера. Игроки видят этап с его первого дня. Этапы не могут пересекаться.
- **Регулярные события.** Повторяются по дням недели или раз в месяц. Могут начинаться и заканчиваться в определённые даты. Если указать персонажа, событие становится его привычкой и показывается в его строке календаря. Можно скрыть от игроков.
- **Скрытые таймеры.** Игроки их не видят. Таймер со сроком появляется в строке «План мастера» в день срока.
- **План мастера.** Игроки его не видят. Можно включить **маску**: тогда игроки увидят на эти дни общее событие с другим текстом (например, «Риг позвал всех к себе в ангар») и не станут ничего на них планировать. Можно указать, кого из персонажей касается маска. Бот сообщает об этом затронутым игрокам.
- **Хроника.** Сыгранные события можно добавлять, править и удалять.
- **Досье.** Кнопка «Добавить карточку» на вкладке «Досье». Карточка изначально скрыта от игроков: откройте её кнопкой в окне карточки или в форме «Изменить карточку» (можно открыть только выбранным персонажам). Сведения добавляются кнопкой «Добавить сведение», у каждого своя видимость и дата, когда пачка это узнала. Если пачка узнала неточное, впишите настоящее в поле «На самом деле»: его видите только вы. Кнопка «Открыть игрокам» у сведения открывает его одним нажатием. Стартовые карточки из байбла все скрыты, их заметки видны только мастеру.
- **Картинки в досье.** В окне карточки кнопка «Добавить картинку»: выберите файл (JPEG, PNG или WebP), перетащите картинку и подберите масштаб, нажмите «Сохранить». Картинка сожмётся сама. В начале вкладки «Досье» видно, сколько места занято. Лимиты задаются в `.env`: `PORTRAIT_QUOTA_MB` (общий объём, по умолчанию 40) и `PORTRAIT_MAX_UPLOAD_MB` (размер одного файла, по умолчанию 8). Если хранилище заполнено, портал попросит убрать ненужные картинки. Картинки хранятся в базе, поэтому каждая резервная копия содержит их все: при 14 копиях и заполненном хранилище на 40 МБ копии займут до 600 МБ диска. Если диск маленький, храните меньше копий: число в конце команды копирования, например `python -m app.backup 7`. Для варианта с nginx в конфиге уже стоит `client_max_body_size 10m`, без него загрузка упрётся в лимит в 1 МБ.
- **Раздатки.** Кнопка «Добавить раздатку» на вкладке «Раздатки»: выберите HTML-файл (название подставится из него), дату получения, кому выдана, комментарий для игроков. Черновик никому не виден; когда раздатку выдают, игроки получают уведомление. «Изменить» в окне раздатки позволяет заменить файл или поменять получателей. Лимиты в `.env`: `HANDOUT_QUOTA_MB` (общий объём, по умолчанию 100) и `HANDOUT_MAX_UPLOAD_MB` (один файл, по умолчанию 15). Для nginx в конфиге стоит `client_max_body_size 16m`.
- **Карта.** Места добавляются кнопкой «Добавить место» и щелчком по карте, двигаются кнопкой «Переместить» в карточке места. Видимость места: все игроки, только знающие персонажи или только мастер. Описания районов правятся в карточке района (щелчок по району).

Файл `config/campaign.json` используется только при самом первом запуске. Команда `python -m app.seed --structure` загружает структуру из него заново и **стирает правки, сделанные в панели**, поэтому перед выполнением спрашивает подтверждение. В обычной работе она не нужна.

### Журналы и перезапуск

```bash
sudo docker compose logs --tail 50 app      # последние строки
sudo docker compose logs -f app             # следить в реальном времени, выход Ctrl+C
sudo docker compose restart app             # перезапуск портала
sudo docker compose up -d                   # после любых правок .env
```

### Если сервер перезагрузился

Ничего делать не нужно: контейнеры поднимутся сами.

## 13. Резервные копии

### Сделать копию вручную

```bash
sudo docker compose exec app python -m app.backup
```

Копия ляжет в `data/backups/`. Хранятся последние 14 штук, старые удаляются сами.

### Каждый день автоматически

```bash
sudo crontab -e
```

Если спросит редактор, выберите `nano`. Добавьте строку в конец:

```
0 5 * * * cd /opt/seattle2075-portal && /usr/bin/docker compose exec -T app python -m app.backup > /dev/null
```

Копия будет делаться каждый день в 5 утра по времени сервера.

### Забрать копии к себе

Раз в какое-то время стоит скачать их на свой компьютер (из PowerShell):

```
scp -r root@IP_СЕРВЕРА:/opt/seattle2075-portal/data/backups .
```

### Восстановить из копии

```bash
cd /opt/seattle2075-portal
sudo docker compose stop app
ls data/backups/                                          # выберите нужный файл
sudo cp data/backups/portal-ГГГГММДД-ЧЧММСС.db data/portal.db
sudo rm -f data/portal.db-wal data/portal.db-shm
sudo chown 1000:1000 data/portal.db
sudo docker compose start app
```

## 14. Обновление портала

Когда появится новая версия архива:

```bash
cd /opt
sudo unzip -o seattle2075-portal-новый.zip -d /tmp/portal-new
sudo rsync -a \
  --exclude .env \
  --exclude data \
  --exclude config/players.toml \
  --exclude config/campaign.json \
  /tmp/portal-new/seattle2075-portal/ /opt/seattle2075-portal/
cd /opt/seattle2075-portal
sudo docker compose up -d --build
sudo rm -rf /tmp/portal-new
```

Ваши `.env`, список игроков, структура кампании и вся база останутся нетронутыми. Если `rsync` не установлен: `sudo apt install -y rsync`. Файл `deploy/Caddyfile` при этом заменяется версией из архива: если вы правили его сами, перенесите правки заново.

Обновлять можно и через WinSCP: загрузите с заменой папки `app` и `static` (а если в описании обновления сказано, то и другие файлы, например `requirements.txt` или `deploy/Caddyfile`), затем выполните `sudo docker compose up -d --build`. После замены `deploy/Caddyfile` достаточно `sudo docker compose restart caddy`.

Перед обновлением не помешает сделать резервную копию (раздел 13).

## 15. Вариант без Docker

Используйте его, если образы Docker не скачиваются или Docker не нужен. Шаги 1–4, 6 и 7 остаются теми же. Шаги 5 и 8 заменяются этим разделом.

### 15.1. Пакеты

```bash
sudo apt install -y python3-venv nginx certbot python3-certbot-nginx rsync
```

### 15.2. Пользователь и окружение

```bash
sudo useradd --system --home /opt/seattle2075-portal portal
cd /opt/seattle2075-portal
sudo python3 -m venv .venv
sudo .venv/bin/pip install -r requirements.txt
sudo mkdir -p data
sudo chown -R portal:portal data
```

### 15.3. Служба портала

```bash
sudo cp deploy/seattle2075-portal.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now seattle2075-portal
sudo systemctl status seattle2075-portal
```

В статусе должно быть `active (running)`. Выход из просмотра статуса: клавиша `q`.

### 15.4. Веб-сервер и HTTPS

```bash
sudo cp deploy/nginx-portal.conf /etc/nginx/sites-available/seattle2075-portal
sudo nano /etc/nginx/sites-available/seattle2075-portal
```

Замените `portal.example.ru` на свой домен. Затем:

```bash
sudo ln -s /etc/nginx/sites-available/seattle2075-portal /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t
sudo systemctl reload nginx
sudo certbot --nginx -d portal.example.ru
```

Certbot спросит почту и согласие с условиями, затем сам получит сертификат и настроит HTTPS. Продлевать сертификат он тоже будет сам.

После этого переходите к разделу 9.

### 15.5. Команды для этого варианта

| Что сделать | Команда |
|---|---|
| Журнал | `sudo journalctl -u seattle2075-portal -n 50` |
| Следить за журналом | `sudo journalctl -u seattle2075-portal -f` |
| Перезапуск, после правки `.env` тоже | `sudo systemctl restart seattle2075-portal` |
| Резервная копия | `cd /opt/seattle2075-portal && sudo -u portal .venv/bin/python -m app.backup` |

Строка для `sudo crontab -e`:

```
0 5 * * * cd /opt/seattle2075-portal && sudo -u portal .venv/bin/python -m app.backup > /dev/null
```

Восстановление из копии идёт как в разделе 13, только портал останавливается командой `sudo systemctl stop seattle2075-portal`, запускается `sudo systemctl start seattle2075-portal`, а владельцем файла базы ставится `portal:portal`.

При обновлении (раздел 14) вместо `docker compose up -d --build` выполните:

```bash
sudo .venv/bin/pip install -r requirements.txt
sudo systemctl restart seattle2075-portal
```

## 16. Проверка на своём компьютере

Портал можно запустить у себя без бота и домена, чтобы посмотреть и потыкать. Нужен Python 3.10 или новее.

**Windows (PowerShell), из распакованной папки проекта:**

```
py -m venv .venv
.venv\Scripts\pip install -r requirements.txt
copy config\players.example.toml config\players.toml
notepad config\players.toml
```

В блокноте впишите тестовые числа: мастеру `telegram_ids = [1]`, Максиму `[2]`, остальным `[3]`, `[4]` и так далее. Сохраните и запустите:

```
$env:DEV_LOGIN="1"; $env:COOKIE_SECURE="0"
.venv\Scripts\uvicorn app.main:app --port 8000
```

**Linux или macOS:**

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp config/players.example.toml config/players.toml   # впишите тестовые числа
DEV_LOGIN=1 COOKIE_SECURE=0 .venv/bin/uvicorn app.main:app --port 8000
```

Откройте `http://127.0.0.1:8000`. Под кнопкой Telegram будет поле для входа по ID: введите `1`, чтобы войти мастером, или `2`, чтобы войти Максимом. Остановить сервер: `Ctrl+C`. Локальная база лежит в папке `data` проекта; удалите её, чтобы начать с чистого листа.

## 17. Если что-то пошло не так

| Что видно | Причина | Что сделать |
|---|---|---|
| Кнопка входа пишет «Bot domain invalid» | Домен не привязан к боту или привязан другой | Повторить шаг 3.2, домен без `https://` |
| Кнопки входа нет совсем | Пустое или неверное `BOT_USERNAME` | Проверить `.env`, затем `sudo docker compose up -d` |
| «Данные входа устарели» | Часы сервера сбиты | Шаг 4.3 |
| «Вашего Telegram нет в списке игроков» | ID не вписан в `players.toml` | Вписать число, нажать «Проверить ещё раз» |
| Сайт не открывается или нет замка | Домен ещё не указывает на сервер, закрыты порты 80/443, порты занял другой веб-сервер | `getent hosts домен`, шаги 4.4 и 4.5, журнал `caddy` |
| В журнале `caddy` ошибки получения сертификата | То же, что выше. После исправления Caddy повторит попытку сам | Исправить причину, затем `sudo docker compose restart caddy` |
| `app` постоянно перезапускается, в журнале `Permission denied` | Нет прав на папку `data` | `sudo chown -R 1000:1000 data`, затем `sudo docker compose restart app` |
| `app` не стартует, в журнале ошибка про `players.toml` | Опечатка в файле: кавычки, запятые, скобки | Исправить строку, указанную в журнале |
| `app` не стартует при первом запуске, в журнале ошибка про `campaign.json` | Синтаксическая ошибка в JSON | `python3 -m json.tool config/campaign.json`, исправить указанную строку |
| `docker compose`: команда не найдена | Не установлен `docker-compose-v2` | Шаг 5 |
| Образы не скачиваются | Нет доступа к Docker Hub с сервера | Раздел 15 |
| Бот не пишет игроку в личку | Игрок не нажал «Запустить», `NOTIFY_DM=0` или неверный `BOT_TOKEN` | Попросить нажать «Запустить»; в журнале `app` будут строки `Telegram 403` |
| В чате стола нет закрепа | Бот не администратор, нет права закреплять, неверный `TG_CHAT_ID` (часто теряют минус) | Раздел 10 |
| Правка `.env` не действует | Контейнер перезапущен, но не пересоздан | `sudo docker compose up -d` |
| Все игроки внезапно вышли из портала | Сменился или удалился `data/secret.key` | Войти заново; ключ не трогать |

Общий порядок поиска проблемы: сначала `sudo docker compose ps` (всё ли запущено), потом `sudo docker compose logs --tail 50 app` и `sudo docker compose logs --tail 50 caddy`. В журнале портала сообщения на русском.
