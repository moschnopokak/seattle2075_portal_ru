# Портал кампании «Сиэтл 2075»

Сайт с календарём кампании: текущая дата в игре, этапы, записи игроков с анкетой, «+», чтобы попроситься в чужую запись, обсуждение под каждой записью, звёзды приоритета, хроника и панель мастера. Вход через Telegram: в браузере кнопкой «Войти через Telegram», внутри Telegram как Mini App. Всё, что игроку видеть не положено (план мастера, скрытые таймеры, будущие этапы, чужие личные записи), сервер отсекает до отправки в браузер.

Состав: Python (FastAPI), SQLite и Pillow (обработка картинок), одна страница без сборки. Хватает самого маленького VPS.

Подробный пошаговый гайд, от покупки сервера до приглашения игроков, лежит в файле `ЗАПУСК.md`. Ниже краткая версия.

## Что понадобится

- VPS с Ubuntu 22.04 или 24.04 и открытыми портами 80 и 443.
- Домен или поддомен, A-запись которого указывает на IP сервера.
- Бот в Telegram.

## 1. Бот

1. В @BotFather: `/newbot`, сохраните токен и имя бота.
2. Там же `/setdomain`, выберите бота и укажите домен портала без `https://`. Без этого кнопка входа на сайте не заработает.
3. Чтобы портал открывался внутри Telegram: `/mybots` → бот → Bot Settings → Menu Button → адрес `https://ваш-домен`. Кнопка появится в чате с ботом.
4. Закреплённый статус в чате стола (по желанию). Добавьте бота в группу и сделайте администратором с правом закреплять сообщения. Напишите в группе `/start@имя_бота` и откройте в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates`. В ответе найдите `"chat":{"id":-100…}`: это число пойдёт в `TG_CHAT_ID`.
5. Личные уведомления (приглашения, ответы, решения по развитию) приходят только тем, кто хотя бы раз открыл бота и нажал «Запустить». Попросите игроков сделать это.

## 2. Файлы на сервере

```bash
sudo mkdir -p /opt/seattle2075-portal
# распакуйте архив в /opt/seattle2075-portal
cd /opt/seattle2075-portal
cp .env.example .env                                  # заполните
cp config/players.example.toml config/players.toml    # впишите игроков
```

В `.env` обязательно: `DOMAIN`, `SITE_URL`, `BOT_TOKEN`, `BOT_USERNAME`. `DEV_LOGIN` на сервере должен быть `0`: если задан `BOT_TOKEN`, портал игнорирует `DEV_LOGIN=1` и пишет об этом в журнал.

В `config/players.toml` за игроками закреплены персонажи; у Максима двое, и у каждого персонажа своя звезда. Людей можно указать по Telegram ID или по имени пользователя. Если ID неизвестен, оставьте список пустым: при входе портал покажет человеку его ID, останется вписать число. Файл перечитывается на лету, перезапуск не нужен.

## 3а. Запуск в Docker

```bash
sudo mkdir -p data && sudo chown 1000:1000 data
docker compose up -d --build
docker compose logs -f app
```

Caddy сам получит сертификат HTTPS для домена из `.env`. Если образы с Docker Hub на сервер не скачиваются, используйте вариант 3б.

## 3б. Запуск без Docker (systemd и nginx)

```bash
sudo apt update && sudo apt install -y python3-venv nginx certbot python3-certbot-nginx
sudo useradd --system --home /opt/seattle2075-portal portal
cd /opt/seattle2075-portal
sudo python3 -m venv .venv
sudo .venv/bin/pip install -r requirements.txt
sudo mkdir -p data && sudo chown -R portal:portal data

sudo cp deploy/seattle2075-portal.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now seattle2075-portal

sudo cp deploy/nginx-portal.conf /etc/nginx/sites-available/seattle2075-portal
sudo nano /etc/nginx/sites-available/seattle2075-portal   # впишите свой домен
sudo ln -s /etc/nginx/sites-available/seattle2075-portal /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d ваш-домен
```

Журнал: `journalctl -u seattle2075-portal -f`.

## 4. Первый вход

1. Откройте `https://ваш-домен` и войдите через Telegram.
2. Если вашего ID нет в `[gm]`, страница покажет число. Впишите его в `telegram_ids` мастера и нажмите «Проверить ещё раз».
3. В панели мастера выставьте текущую дату («Перейти к дате»), время суток и свободное время.
4. Разошлите игрокам ссылку. Кого нет в списке, увидит свой ID и перешлёт его вам.

## Повседневная работа

**Время в игре** двигается в панели мастера. Если задан `TG_CHAT_ID`, бот сам обновит закреплённое сообщение в чате стола.

**Этапы, регулярные события, скрытые таймеры, план мастера и хроника** редактируются в панели мастера на сайте: у каждого раздела есть кнопка «Добавить», а открытое событие можно изменить или удалить. Файл `config/campaign.json` нужен только для первого запуска. Команда `python -m app.seed --structure` заново загружает структуру из него, стирая правки из панели, поэтому перед выполнением она спрашивает подтверждение.

**Карта.** Раздел «Карта» — собственная векторная карта Сиэтла 2075 года: вода, районы, Аутремер, Догтаун со стеной и пропускными пунктами, дороги трёх уровней с номерами магистралей, сетка квадратов 5×5 км. Дороги взяты из OpenStreetMap (подпись «© участники OpenStreetMap» в углу карты обязательна по лицензии ODbL). Данные лежат в `static/map/map.json`, библиотека Leaflet — в `static/vendor`, внешние сервисы не нужны. Места на карте мастер добавляет кнопкой «Добавить место» и щелчком по карте, двигает кнопкой «Переместить» в карточке места. У места три уровня видимости: все игроки, только знающие персонажи, только мастер. Заметка мастера игрокам не отправляется. Запись календаря можно привязать к месту: в карточке места видны её записи, а из записи можно перейти на карту. Описания районов правятся в карточке района.

**Импорт мест и фон.** Кнопка «Импорт мест» у мастера на карте добавляет места пачкой: либо из встроенного набора точек книги «Seattle 2072» (открытый набор skiant/seattle-2072-map, MIT; рекомендуемые отмечены заранее, то, что уже есть на карте, не отмечено), либо из своего файла KML (Google My Maps: меню карты, «Экспорт в KML/KMZ», галочка «Экспортировать в файл .KML»; тип задаётся для каждого слоя). Выбирается, кто увидит новые места: все игроки или только мастер. Место можно пометить как фоновое (магазины, еда, ночлег): такие места прячутся переключателем «Фон» рядом с «Места», «Дороги» и «Сетка», а их подписи уступают подписям мест пачки. Новые типы мест: медицина, полиция и тюрьмы, магазины, еда и отдых. Существующие места импорт не меняет, весь импорт одна запись в журнале изменений, за раз не больше 600 мест, всего на карте не больше 1500.

**Линейка и время в пути.** Кнопка «Линейка» на карте. Щёлкаете по карте или по метке места, ставите две и больше точек (их можно перетаскивать, убирать, менять местами) и сразу видите расстояние и время для каждого вида транспорта. В режиме «По дорогам» маршрут ищется по дорогам карты (магистрали, трассы, основные) по времени: быстрая дорога может оказаться выгоднее короткой. Участок от точки до ближайшей дороги считается как «вне дорог». В данных дорог местами выпадают куски (развязки, мосты), поэтому концы линий, между которыми меньше 500 м и короткого объезда нет, «сшиваются»: без этого маршрут из Сноухомиша в Беллвью шёл в обход через Эверетт, 70 км вместо 44. Если дороги далеко или связи нет, участок считается по прямой, и это видно в таблице. В режиме «По прямой» просто измеряется расстояние. Нажатие на вид транспорта в таблице показывает на карте его маршрут. Кнопка «Расстояние отсюда» в карточке места начинает измерение с этого места. Виды транспорта (скорости по классам дорог, вне дорог, сборы и остановки, минуты на пропускном пункте Догтауна) мастер редактирует в панели мастера, раздел «Транспорт и скорости»: можно добавить свои (метролинк, байк, катер) и скрыть от игроков. Вид «по прямой» нужен для вертолёта и дронов. Скорость 0 на классе дорог значит, что по таким дорогам этот транспорт не ездит. Расчёт идёт целиком в браузере по данным `static/map/map.json`; это оценка без пробок и происшествий. Движок (`static/js/geo.js`) покрыт тестами на синтетических сетях и на настоящей карте.

**Досье.** Вкладка «Досье»: карточки людей и организаций, с которыми пачка сталкивалась. У карточки есть имя, позывной, короткая строка «кто это», отношение пачки (контакт, союзник, нейтрален, враг, неясно), организация, список персонажей, знакомых лично, последняя встреча (дата и место с карты) и список сведений. Поиск ищет по имени, организации и открытым сведениям, у мастера ещё по заметкам и поправкам. Видимость работает на двух уровнях: карточка открыта всем, только знающим персонажам или скрыта от игроков, и у каждого сведения своя видимость. Игрок получает только то, что открыто его персонажам; заметка мастера и поправка «на самом деле» (для сведений, в которых пачка ошибается) на его устройство не отправляются. При первом запуске из `config/campaign.json` загружаются 57 скрытых карточек с заметками из байбла (раздел 9 и справки по фракциям). Загрузка происходит один раз, потом досье правится только в портале.

**Картинки в досье.** К карточке можно добавить картинку (портрет человека или эмблему организации). Мастер выбирает файл, в браузере подбирает кадр (перетаскивание и масштаб), картинка сжимается до квадрата. Сервер перекодирует её ещё раз в два WebP: 480×480 для карточки (до 90 КБ) и 96×96 для списка (до 10 КБ); метаданные, в том числе координаты съёмки, при этом удаляются. Память ограничена двумя лимитами: общий объём всех картинок (`PORTRAIT_QUOTA_MB`, по умолчанию 40 МБ) и размер загружаемого файла (`PORTRAIT_MAX_UPLOAD_MB`, по умолчанию 8 МБ). Слишком большие по разрешению, повреждённые и не-картинки отклоняются с понятным сообщением. Картинки хранятся в базе и попадают в резервные копии. Адрес картинки содержит случайный токен, который получают только те игроки, кому открыта карточка, и который меняется при замене.

**Раздатки.** Вкладка «Раздатки»: то, что пачка получила на руки. Это может быть HTML-страница, картинка (PNG, JPEG, GIF, WebP), PDF или аудио (MP3, M4A, OGG, WAV, FLAC, WebM). Тип определяется по содержимому файла, а не по расширению. Мастер загружает файл, указывает дату получения, кому выдана (всей пачке, отдельным персонажам или черновик), комментарий для игроков, место на карте и заметку для себя. Игроки видят только выданное им, получают уведомление в Telegram, на вкладке отмечено число непросмотренных. Раздатка открывается на весь экран, есть переход к дню в календаре и к месту на карте; в хронике раздатки показаны в своём этапе. Файл хранится в базе и попадает в резервные копии (HTML в сжатом виде, текст сжимается в 5–50 раз; картинки, PDF и звук как есть). Картинки при загрузке перекодируются без метаданных (пропадают координаты съёмки и прочее), поворот из метки применяется, до 60 мегапикселей; анимированные GIF сохраняются как есть. В окне просмотра картинка увеличивается нажатием, у звука есть проигрыватель с перемоткой, PDF показывается в рамке (на телефонах встроенного просмотра может не быть, поэтому есть кнопки «Открыть отдельно» и «Скачать»). Лимиты: `HANDOUT_QUOTA_MB` (общий объём в сжатом виде, по умолчанию 100 МБ) и `HANDOUT_MAX_UPLOAD_MB` (один файл, по умолчанию 15 МБ). HTML открывается в «песочнице» (заголовок `Content-Security-Policy: sandbox`; картинки, PDF и звук отдаются с точным типом и запретом угадывания типа, `nosniff`): его скрипты работают, но не видят ни страницу портала, ни вход, ни API, даже если открыть ссылку отдельно. Из-за этого внутри раздатки не работает `localStorage`. Если раздатка умеет масштабироваться (раздатки, которые собирает Claude, содержат для этого небольшой встроенный скрипт), просмотрщик показывает кнопки «−», «+» и «по ширине»: на телефоне лист A4 вписывается целиком и приближается кнопками, щипком или двойным касанием. Остальные HTML открываются как есть.

**Что было раньше (пересказ).** Если задан `ANTHROPIC_API_KEY`, на вкладке «Хроника» у игрока появляется кнопка «Что было раньше»: он выбирает период (последняя сессия, две последние, неделя или своя дата), и Claude (Anthropic API, официальный SDK `anthropic`) пишет короткий пересказ пропущенного. В запрос уходит только то, что видит сам игрок: из того же состояния, которое портал отдаёт этому игроку (хроника, сведения досье с датами, полученные раздатки, его сыгранные записи). Заметки мастера, скрытые карточки и чужие личные записи не попадают в запрос, поэтому раскрыть их модель не может. Материалы передаются как данные в тегах `<data>` (угловые скобки в них заменяются), инструкции лежат в системном сообщении, а ответ показывается обычным текстом. По умолчанию модель `claude-opus-5-5` с глубиной размышления `low` и серверным `fallbacks: "default"` (если защитный классификатор откажет, Anthropic сам повторит запрос на другой модели); `RECAP_MODEL` и `RECAP_EFFORT` меняют их. Готовые пересказы запоминаются на 90 дней (тот же запрос повторно ничего не стоит), новых можно заказать `RECAP_PER_DAY` в сутки на игрока (6) и `RECAP_DAILY_TOTAL` на весь портал (40). Без ключа кнопки нет. Мастеру пересказ не нужен.

**Пересказ через мастера (без ключа и без оплаты).** С `RECAP_MODE=gm` пересказ пишет не портал, а сам мастер в своём обычном чате с Claude, под лимиты своей подписки; ключ API не нужен, и никуда ничего не отправляется. Игрок нажимает «Попросить пересказ», портал собирает тот же запрос, что и в первом режиме (правила и материалы только из того, что видит этот игрок), кладёт его в панель мастера в раздел «Просьбы о пересказе» и пишет мастеру в Telegram. Мастер нажимает «Скопировать запрос для Claude», вставляет его в свой чат, читает ответ, вставляет его в поле «Ответ Claude» и нажимает «Отправить игроку» (или «Отказать» с короткой причиной). Игрок получает сообщение от бота, а на кнопке «Что было раньше» появляется метка «ответ готов»; список его просьб и ответов лежит в том же окне. У одного персонажа одна открытая просьба: новая заменяет прежнюю (старый запрос в чате мастера после этого отправить игроку нельзя, портал это не даст). Тот же период с теми же материалами второй раз берётся из готового ответа. Предел: `RECAP_PER_DAY` просьб в сутки на игрока (замены тоже считаются) и не больше 30 открытых просьб на весь портал. Вставляемый ответ до 6000 знаков, показывается игроку обычным текстом. Просьбы и ответы хранятся 90 дней. Режим включается одной строкой в `.env`, после чего портал перезапускается.

**Мой дневник.** Кнопка «Мой дневник» вверху портала (у игрока, у мастера в предпросмотре «как видит игрок»): скачивает всё, что знает персонаж, одним файлом, Markdown (для Obsidian и других заметок, со ссылками `[[Имя]]`) или PDF (для чтения и печати, шрифт DejaVu Serif лежит в `app/fonts/` и умеет кириллицу). Можно выбрать, что включить: хроника, мои записи, обсуждения записей, досье, раздатки (названия и описания), лист персонажа. Файл собирает сервер из того же состояния, которое он отдаёт этому игроку, поэтому в нём нет ничего, чего игрок не видит: заметок мастера, скрытых карточек, чужих личных записей, данных других персонажей. Не больше 10 файлов в минуту на человека. Для PDF нужна библиотека `fpdf2` (есть в `requirements.txt`).

**Лист персонажа (Shadowrun).** Вкладка «Лист»: нуйены, репутация по фракциям и контакты персонажа. Данные ведёт мастер (вкладка «Лист» у мастера: сводка по всем персонажам, выбор персонажа, формы и список фракций). Для нуйенов мастер записывает, сколько денег пришло или ушло, с пояснением и датой (кнопка «Записать доход или расход»), а общая сумма считается сама. Фракции (корпорации, банды, власти, организации) мастер открывает всем, отмеченным персонажам или скрывает; репутация персонажа у фракции это число от −5 («объявлена охота») до +5 («свой») с подписью и пометкой. Контакт это имя (можно привязать к карточке досье), «Связи» 1–12 и «Лояльность» 1–6, чем помогает и заметка. Игрок видит только своё, и репутацию только у тех фракций, о которых его персонаж знает; заметки мастера до игроков не доходят, ссылка на карточку досье показывается, только если карточка открыта персонажу. Все правки идут через журнал изменений и корзину, у каждой строки есть «История».

**Кубы в обсуждении.** В обсуждении записи (участникам и мастеру) есть «Бросить кубы»: число кубов до 40, необязательные «предел» и «порог», «рискнуть» и подпись. Правила Shadowrun 5: успех это 5 и 6; глитч, если единиц больше половины пула, критический глитч, если при этом нет успехов; предел урезает засчитанные успехи; «рискнуть» (Edge, Push the Limit) делает шестёрки взрывными и отключает предел; порог показывает успех или провал проверки. Кубы бросает сервер (`secrets`), результат остаётся в обсуждении сообщением с нарисованными кубиками и видят его все участники; не больше 30 бросков в минуту на человека. Бот присылает короткий текст результата, как обычное сообщение.

**Ссылки на карточки досье.** В любом свободном тексте (цель и условие записи, обсуждение, хроника, места, районы, сведения и роль в карточке) можно написать `[[Имя]]` или `[[Имя|как показать]]`: имя превратится в ссылку, которая открывает карточку (ищется по имени или позывному, без учёта регистра и «ё»). Ссылка работает только на карточки, которые видит сам читающий. Если такой карточки нет или она скрыта, показывается просто имя без ссылки, так что по тексту нельзя узнать, что скрытая карточка существует. Мастер видит такие ссылки подчёркнутыми красным пунктиром, чтобы заметить опечатку. В карточке есть блок «Упоминается»: записи, хроника, места и (у мастера) планы, где на неё сослались и которые видит читающий. В сообщениях бота скобки убираются, остаётся имя.

**Кто свободен.** В форме новой записи под датами показано, кто из выбранных участников занят в эти дни и на это время суток: встречи и дела (развитие и обещания время не занимают), общие события мастера и привычки персонажей. Приглашение без ответа и запись, которой нужна другая дата, дают «возможно занят(а)». Если кто-то занят, ниже предлагаются ближайшие дни, когда свободны все (в пределах 60 дней), и нажатие на день подставляет его в форму. Считается только по тому, что видит сам человек: чужие личные записи и маски мастера для других персонажей не показываются. При правке записи она сама себя не занимает.

**Кнопки в сообщениях бота.** С `TG_WEBHOOK=1` (и `SITE_URL` с https) под приглашением в запись появляются «Принять» и «Отклонить», а мастеру под заявкой на развитие «Подтвердить» и «Отклонить»: ответить можно, не открывая портал. Нажатия приходят на `/api/telegram/webhook` и выполняются теми же правилами, что на портале, от имени нажавшего. Пока webhook включён, `getUpdates` у бота не работает (`python -m app.telegram_bot delete` выключает). Подробнее в `ЗАПУСК.md`, раздел 10.4.

**Личные уведомления.** Бот пишет человеку лично, если тот нажал «Запустить» (приглашения, ответы, развитие, раздатки, общие события). Новые сообщения в обсуждении записи приходят одним уведомлением примерно через `CHAT_NOTIFY_DELAY` секунд (по умолчанию 300) после первого. Если игрок не ответил на приглашение, через `REMIND_DAYS` дней (по умолчанию 2) бот напомнит, потом ещё раз (всего `REMIND_MAX`, по умолчанию 2); `REMIND_DAYS=0` выключает напоминания. Кнопка «Уведомления» вверху портала открывает личные настройки: режим «сразу» или «одной сводкой раз в день», тихие часы, часовой пояс (до выбора действует `DEFAULT_TZ`), пробное сообщение. Уведомления идут через очередь в базе с повторными попытками; её разбирает фоновый планировщик (`SCHEDULER=1`).

**Что видят игроки вперёд.** Панель мастера, раздел «Что видят игроки вперёд» (по умолчанию выключено, как и было). Если выбрать «До конца текущего этапа», игроки не видят и не могут назвать дату позже последнего дня того этапа, в который входит сегодняшний день в игре. Для игроков портал убирает из состояния всё, что начинается позже этой границы: записи календаря (в том числе приглашения мастера), общие события (маска плана), регулярные события с более поздним началом, раздатки и сведения в досье с более поздней датой и хронику с более поздней датой. Что началось раньше и заканчивается позже, показывается только до границы. Календарь игрока обрывается на границе, а при создании или переносе записи дата позже границы отклоняется понятной ошибкой (для заявки на развитие это касается и даты «Действует с»). Граница сдвигается сама, когда игровая дата переходит в следующий этап; мастер видит всё, а как это выглядит для игрока, показывает выбор «Вид» вверху. Уведомления «Общее событие» и «Новая раздатка» о том, что лежит дальше границы, не отправляются. Если сегодняшний день не входит ни в один этап, ограничение не действует, и панель мастера об этом сообщает. Переключение пишется в журнал («изменил(а) настройку»). Код: `logic.horizon()`, `POST /api/gm/horizon`.

**Загрузка разбора арки.** Панель мастера, раздел «Загрузить разбор арки». События арки, подготовленные в другом чате по промпту (`ПРОМПТ_РАЗБОР_АРОК.md`: чат отвечает кратким обзором, блоком `json` и вопросами мастеру), добавляются разом: этапы, план мастера, скрытые таймеры, регулярные события, записи календаря (встреча, дело, обещание от имени мастера), хроника, досье, места и раздатки. Мастер вставляет ответ чата целиком, портал сам находит в нём блок `json` и по кнопке «Проверить» показывает отчёт: что добавится, что уже есть, что не пройдёт проверку и почему (каждый элемент проходит ту же проверку, что и ручное добавление через форму). Пока не нажата «Добавить», ничего не записывается; при записи всё проверяется заново и пишется одной транзакцией и одной записью в журнале («Импорт разбора арки»), при сбое не остаётся ничего. Что не прошло проверку, пропускается, остальное добавляется. То же название и те же даты считаются уже имеющимся и пропускаются, поэтому повторная загрузка безопасна, а существующее не затирается. Единственное исключение только дополняет: если карточка досье или место с таким именем уже есть, к карточке добавляются сведения, которых в ней нет (по тексту), и дописывается заметка мастера (под пометкой «Из разбора арки», не длиннее предела поля), к месту дописывается заметка мастера; остальные поля (роль, видимость, позывной, точка на карте и другое) не меняются. Каждое такое дополнение пишется в журнал отдельной записью и отменяется кнопкой «Вернуть как было». Игрокам при загрузке ничего не отправляется: ни уведомлений, ни «общих событий» заранее. Места приходят без координат (район и ориентир): они ставятся рядом с центром района, по умолчанию видны только мастеру, и их остаётся перетащить кнопкой «Переместить». Записи календаря и раздатки ссылаются на место по названию (`place_name`); черновик текста раздатки кладётся в заметку мастера, сам файл мастер загружает отдельно. За раз до 400 пунктов. Интерфейс: `static/js/arcs.js`, проверка и запись: `app/arcs.py`, на портале `POST /api/gm/arc/preview` и `/api/gm/arc/import`. Пример из промпта проверяется автотестом на настоящую загрузку, так что промпт и портал не разойдутся.

**Корзина и история изменений.** В панели мастера, внизу. Всё, что удалено (запись календаря вместе с обсуждением, карточка досье, место, раздатка, этап, таймер и так далее), попадает в корзину и хранится `TRASH_DAYS` дней (по умолчанию 30), оттуда это можно восстановить одной кнопкой или удалить окончательно. Картинка и файл удалённого остаются в базе, но по ссылке не открываются и в лимит не входят; при восстановлении выдаётся новая ссылка. История изменений показывает, кто, когда и что менял, включая действия игроков (создание, правки и удаление записей, ответы на приглашения и другое), хранится `AUDIT_DAYS` дней (по умолчанию 365). У правки можно раскрыть «Что изменилось» (было и стало) и нажать «Откатить»: прежние значения вернутся. Можно отменить добавление, вернуть удалённое, вернуть время в игре. Поиск идёт по названию и имени. Историю одного элемента можно открыть кнопкой «История» в карточке досье или записи. Игроки корзину и журнал не видят. Версии базы ведутся автоматически (`PRAGMA user_version`): при обновлении портал сам приводит старую базу к новой схеме.

**Копия данных для Obsidian.** В панели мастера кнопка «Собрать текст для копирования» собирает всё содержимое портала в одну заметку Markdown: календарь, хронику с заметками мастера, записи с обсуждениями, этапы, план, таймеры, регулярные события, места на карте, описания районов, раздатки и досье. Это удобная читаемая копия ваших записей в дополнение к резервным копиям базы.

**Общее событие вместо плана мастера.** У события плана можно включить «Показать игрокам как общее событие»: игроки увидят на эти дни общее событие с другим текстом, например «Риг позвал всех к себе в ангар», и не станут ничего на них планировать. Настоящее описание на их устройства не попадает. Бот сообщает затронутым игрокам о новом или изменённом общем событии.

**Видимость этапов.** Игроки видят название этапа с его первого дня. Поле `name` показывается игрокам, поле `gm` только мастеру. Регулярные события с `"vis": "мастер"` игрокам не видны.

**Резервные копии.** `python -m app.backup` кладёт проверенную копию базы в `data/backups` и хранит последние 14. Ежедневная копия в 5 утра:

```
0 5 * * * cd /opt/seattle2075-portal && docker compose exec -T app python -m app.backup
```

Без Docker: `0 5 * * * cd /opt/seattle2075-portal && set -a && . ./.env && set +a && sudo -E -u portal .venv/bin/python -m app.backup`.

Чтобы копии были не только на сервере, поставьте в `.env` `BACKUP_TELEGRAM=1`: каждая копия уйдёт мастеру в личные сообщения от бота (сжатая, до 50 МБ). Можно также забирать папку `data/backups` через `scp` или `rclone` (см. `ЗАПУСК.md`, раздел 13). `python -m app.backup --verify` проверяет копию и показывает, что в ней лежит; `python -m app.backup --restore ФАЙЛ` восстанавливает базу (портал на это время останавливается, прежняя база сохраняется как `before-restore-….db`). Коды возврата: 0 всё хорошо, 1 ошибка, 2 копия сделана, но в Telegram не ушла. Если задан `HEALTHCHECKS_URL`, после каждой копии подаётся «пульс» в healthchecks.io: сервис сам напишет вам, если копия не сделалась или cron перестал работать (`ЗАПУСК.md`, раздел 13).

**Обновление кода.** Замените папки `app/` и `static/`, затем `docker compose up -d --build` или `sudo systemctl restart seattle2075-portal`. Данные в `data/` сохраняются.

## Автотесты

Интерфейс (`static/js`) проверяют отдельно: `npm ci && npm run lint && npm test`. ESLint ловит опечатки в именах и запрещённые конструкции (`eval`, `new Function`, `javascript:`), `npm test` запускает тесты чистых функций на `node:test`. Сам портал собирать не нужно: `static/` отдаётся как есть.

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/pytest -m "not browser"      # быстрые проверки, около минуты
.venv/bin/playwright install chromium  # один раз
.venv/bin/pytest -m browser            # проверки в настоящем браузере
```

Тесты идут на отдельной временной базе и на вымышленной кампании из `tests/fixtures/` (все «секреты» в ней начинаются со слова «СЕКРЕТ»), ваши данные они не трогают. Что проверяется: вход и подписи Telegram, права мастера и игрока, что ни один секрет мастера не доходит до игрока, сценарии записей, загрузки картинок и раздаток, отзыв ссылок при сужении доступа, устойчивость к мусору в запросах (любое поле любого запроса заменяется на списки, словари, `null` и огромные числа: ответ должен быть 4xx, не 500), а в браузере ещё и то, что чужой текст не исполняется как код ни на одной странице. Дальше по новым возможностям: очередь уведомлений и тихие часы (на подставных часах и подставном Telegram), кнопки бота и защита webhook, напоминания, видимость листа персонажа и «Мой дневник» (в файле не должно быть секретов мастера и чужих данных), правила кубов (на подставных кубах), типы файлов раздаток и перекодирование картинок, поиск свободных дней и ссылки `[[Имя]]` (в Node и в браузере), пересказ «Что было раньше» (клиент Claude подменён заглушкой, настоящий API не вызывается). В `tests/media.py` лежат образцы файлов для раздаток. Ключевые проверки прогонялись «мутациями»: код намеренно ломался, и тест обязан был упасть.

Вёрстку шапки проверяет `tests/test_ui_layout.py` в настоящем браузере: на ширине от 761 px ни одна вкладка не прячется за край, на телефонах кнопки шапки не разъезжаются (проверка появилась после покадрового сравнения с прежней версией). Отдельно проверено обновление работающего портала: `tests/test_legacy_upgrade.py` берёт базу, которую наполнил настоящий код первой версии (`tests/fixtures/legacy_v1.*`), и убеждается, что новая версия открывает её без потерь, мастер и игроки видят то же, что видели, входные cookie остаются в силе, а репетиция ловит потерю и подмену данных. `tests/test_update_scripts.py` прогоняет `deploy/update.sh` и `rollback.sh` на заглушке docker: успех, отмена, провал репетиции, зависший запуск, потеря данных после запуска, обрыв связи, WAL с незаписанными данными, ручной откат.

Всё это запускается в GitHub Actions на каждый пуш (CI: быстрые тесты, ESLint и тесты JS, браузерные тесты, сборка образа). Если Chromium лежит в нестандартном месте, укажите путь в `PORTAL_TEST_CHROMIUM`. ESLint падает, если одно имя верхнего уровня объявлено в двух файлах `static/js` (скрипты делят общую область, и браузер не запустил бы второй).

## Репозиторий и сборка на GitHub

Настоящий `config/campaign.json` содержит заметки мастера и скрытые карточки досье, поэтому он занесён в `.gitignore` и в репозиторий не попадает. Вместо него лежит пустая заготовка `config/campaign.example.json`. Для нового развёртывания без своих данных скопируйте её: `cp config/campaign.example.json config/campaign.json`. Свой файл кладите на сервер вручную (например, через `scp`), в репозиторий его добавлять не нужно.

Workflow `.github/workflows/ci.yml` на каждый пуш и на каждый pull request в `main` запускает пять заданий:

1. **Запуск приложения**: страница, карта и `/api/state` без входа (должен быть 401) отвечают как надо, файл службы systemd проходит проверку и оценку защищённости.
2. **Автотесты**: `pyflakes` и весь `pytest` без браузера.
3. **Проверки в браузере**: Chromium открывает все разделы с вредными строками в каждом поле.
4. **Docker**: образ собирается, контейнер запускается в усиленном режиме (файловая система только для чтения, без привилегий) до состояния `healthy`, внутри делается резервная копия. Заодно проверяются `Caddyfile` (`caddy validate`), конфиг nginx (`nginx -t`) и оба compose-файла.
5. **Публикация образа**: только для ветки `main` и тегов вида `v1.2.3`, и только если всё выше зелёное. Образ кладётся в GitHub Container Registry: `ghcr.io/moschnopokak/seattle2075_portal_ru` с метками `latest`, хеш коммита и номер версии. В образе нет ни `.env`, ни данных кампании, только код, шрифты и карта.

Выпустить версию: `git tag v1.0.0 && git push origin v1.0.0`. Образ появится с меткой `1.0.0`. Сервер можно обновлять одной командой без сборки на нём (`ЗАПУСК.md`, раздел 14, способ В).

Раз в неделю Dependabot сам присылает pull request'ы с обновлениями библиотек, базового образа Docker и самих действий GitHub Actions. Каждый из них проходит те же проверки, так что ломающее обновление видно сразу.

Результат виден на вкладке **Actions**. Токен бота и другие секреты для проверок не нужны.

## Внешние обращения страницы

Карта, шрифты и остальная статика лежат на самом сервере. Браузер обращается наружу только за двумя скриптами Telegram (`telegram.org`: вход на сайте и работа внутри Telegram), Telegram требует грузить их именно оттуда. Если Telegram недоступен, страница всё равно открывается, не работает только вход.

## Безопасность

- В `data/secret.key` лежит ключ подписи сессий. Если его сменить, все выйдут из портала.
- Telegram ID надёжнее имени пользователя: имя можно сменить или освободить.
- Выйти из портала можно кнопкой «Выйти» в шапке. Закрыть доступ человеку: удалить его из `players.toml`.

**Что защищает портал на уровне сервера.**
- HTTPS с заголовком HSTS (Caddy или nginx): браузер год ходит на сайт только по `https`.
- Страницу нельзя встроить на чужой сайт (`frame-ancestors`), разрешены только сам портал и веб-версии Telegram.
- Cookie входа с флагами `HttpOnly`, `Secure`, `SameSite=Lax`.
- Раздатки открываются в изолированной «песочнице» браузера: их скрипты не видят ни портал, ни вход.
- Ссылки на раздатки и картинки досье меняются, когда доступ к ним сужается или закрывается.
- Docker: контейнер портала работает с файловой системой только для чтения (пишет лишь в `data/`), без привилегий, с проверкой состояния и ограничением размера журналов. Без Docker: служба systemd запущена в «песочнице» (оценка `systemd-analyze security` около 3.4 из 10, чем меньше, тем лучше).
- Запросы ограничены по размеру на уровне веб-сервера (16 МБ).
- В `index.html` нет ни одного inline-скрипта, стиля или обработчика события (это проверяет тест), поэтому можно включить строгую политику CSP: скрипты только с нашего сервера и из `telegram.org`. Режим задаётся `CSP_MODE`: `report-only` (по умолчанию) только пишет нарушения в журнал строками «CSP: …», `enforce` блокирует. Рекомендуемый порядок: неделю поработать в `report-only`, убедиться, что в журнале нет строк «CSP:», затем поставить `CSP_MODE=enforce` и `docker compose up -d`. Кнопка входа Telegram работает через редирект (`/auth/telegram`), старый способ с JS-обработчиком включается `TG_WIDGET_MODE=callback`.
- Если задан `BOT_TOKEN`, вход без Telegram (`DEV_LOGIN`) не работает, даже если его включили по ошибке.
