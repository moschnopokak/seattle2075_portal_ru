# Портал кампании «Сиэтл 2075»

Сайт с календарём кампании: текущая дата в игре, этапы, записи игроков с анкетой, «+» для напрашивания, обсуждение под каждой записью, звёзды приоритета, хроника и панель мастера. Вход через Telegram: в браузере кнопкой «Войти через Telegram», внутри Telegram как Mini App. Всё, что игроку видеть не положено (план мастера, скрытые таймеры, будущие этапы, чужие личные записи), сервер отсекает до отправки в браузер.

Состав: Python (FastAPI), SQLite и Pillow (обработка картинок), одна страница без сборки. Хватает самого маленького VPS.

Подробный пошаговый гайд, от покупки сервера до приглашения игроков, лежит в файле `ЗАПУСК.md`. Ниже краткая версия.

## Что понадобится

- VPS с Ubuntu 22.04 или 24.04 и открытыми портами 80 и 443.
- Домен или поддомен, A-запись которого указывает на IP сервера.
- Бот в Telegram.

## 1. Бот

1. В @BotFather: `/newbot`, сохраните токен и имя бота.
2. Там же `/setdomain`, выберите бота и укажите домен портала без `https://`. Без этого кнопка входа на сайте не заработает.
3. Чтобы портал открывался внутри Telegram: `/mybots` → бот → Bot Settings → Menu Button → адрес `https://ваш-домен`. Кнопка появится в чате с ботом.
4. Закреплённый статус в чате стола (по желанию). Добавьте бота в группу и сделайте администратором с правом закреплять сообщения. Напишите в группе `/start@имя_бота` и откройте в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates`. В ответе найдите `"chat":{"id":-100…}`: это число пойдёт в `TG_CHAT_ID`.
5. Личные уведомления (приглашения, ответы, решения по развитию) приходят только тем, кто хотя бы раз открыл бота и нажал «Запустить». Попросите игроков сделать это.

## 2. Файлы на сервере

```bash
sudo mkdir -p /opt/seattle2075-portal
# распакуйте архив в /opt/seattle2075-portal
cd /opt/seattle2075-portal
cp .env.example .env                                  # заполните
cp config/players.example.toml config/players.toml    # впишите игроков
```

В `.env` обязательно: `DOMAIN`, `SITE_URL`, `BOT_TOKEN`, `BOT_USERNAME`. `DEV_LOGIN` на сервере должен быть `0`: если задан `BOT_TOKEN`, портал игнорирует `DEV_LOGIN=1` и пишет об этом в журнал.

В `config/players.toml` за игроками закреплены персонажи; у Максима двое, и у каждого персонажа своя звезда. Людей можно указать по Telegram ID или по имени пользователя. Если ID неизвестен, оставьте список пустым: при входе портал покажет человеку его ID, останется вписать число. Файл перечитывается на лету, перезапуск не нужен.

## 3а. Запуск в Docker

```bash
sudo mkdir -p data && sudo chown 1000:1000 data
docker compose up -d --build
docker compose logs -f app
```

Caddy сам получит сертификат HTTPS для домена из `.env`. Если образы с Docker Hub на сервер не скачиваются, используйте вариант 3б.

## 3б. Запуск без Docker (systemd и nginx)

```bash
sudo apt update && sudo apt install -y python3-venv nginx certbot python3-certbot-nginx
sudo useradd --system --home /opt/seattle2075-portal portal
cd /opt/seattle2075-portal
sudo python3 -m venv .venv
sudo .venv/bin/pip install -r requirements.txt
sudo mkdir -p data && sudo chown -R portal:portal data

sudo cp deploy/seattle2075-portal.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now seattle2075-portal

sudo cp deploy/nginx-portal.conf /etc/nginx/sites-available/seattle2075-portal
sudo nano /etc/nginx/sites-available/seattle2075-portal   # впишите свой домен
sudo ln -s /etc/nginx/sites-available/seattle2075-portal /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d ваш-домен
```

Журнал: `journalctl -u seattle2075-portal -f`.

## 4. Первый вход

1. Откройте `https://ваш-домен` и войдите через Telegram.
2. Если вашего ID нет в `[gm]`, страница покажет число. Впишите его в `telegram_ids` мастера и нажмите «Проверить ещё раз».
3. В панели мастера выставьте текущую дату («Перейти к дате»), время суток и свободное время.
4. Разошлите игрокам ссылку. Кого нет в списке, увидит свой ID и перешлёт его вам.

## Повседневная работа

**Время в игре** двигается в панели мастера. Если задан `TG_CHAT_ID`, бот сам обновит закреплённое сообщение в чате стола.

**Этапы, регулярные события, скрытые таймеры, план мастера и хроника** редактируются в панели мастера на сайте: у каждого раздела есть кнопка «Добавить», а открытое событие можно изменить или удалить. Файл `config/campaign.json` нужен только для первого запуска. Команда `python -m app.seed --structure` заново загружает структуру из него, стирая правки из панели, поэтому перед выполнением она спрашивает подтверждение.

**Карта.** Раздел «Карта» — собственная векторная карта Сиэтла 2075 года: вода, районы, Аутремер, Догтаун со стеной и пропускными пунктами, дороги трёх уровней с номерами магистралей, сетка квадратов 5×5 км. Дороги взяты из OpenStreetMap (подпись «© участники OpenStreetMap» в углу карты обязательна по лицензии ODbL). Данные лежат в `static/map/map.json`, библиотека Leaflet — в `static/vendor`, внешние сервисы не нужны. Места на карте мастер добавляет кнопкой «Добавить место» и щелчком по карте, двигает кнопкой «Переместить» в карточке места. У места три уровня видимости: все игроки, только знающие персонажи, только мастер. Заметка мастера игрокам не отправляется. Запись календаря можно привязать к месту: в карточке места видны её записи, а из записи можно перейти на карту. Описания районов правятся в карточке района.

**Линейка и время в пути.** Кнопка «Линейка» на карте. Щёлкаете по карте или по метке места, ставите две и больше точек (их можно перетаскивать, убирать, менять местами) и сразу видите расстояние и время для каждого вида транспорта. В режиме «По дорогам» маршрут ищется по дорогам карты (магистрали, трассы, основные) по времени: быстрая дорога может оказаться выгоднее короткой. Участок от точки до ближайшей дороги считается как «вне дорог». Если дороги далеко или связи нет, участок считается по прямой, и это видно в таблице. В режиме «По прямой» просто измеряется расстояние. Нажатие на вид транспорта в таблице показывает на карте его маршрут. Кнопка «Расстояние отсюда» в карточке места начинает измерение с этого места. Виды транспорта (скорости по классам дорог, вне дорог, сборы и остановки, минуты на пропускном пункте Догтауна) мастер редактирует в панели мастера, раздел «Транспорт и скорости»: можно добавить свои (метролинк, байк, катер) и скрыть от игроков. Вид «по прямой» нужен для вертолёта и дронов. Скорость 0 на классе дорог значит, что по таким дорогам этот транспорт не ездит. Расчёт идёт целиком в браузере по данным `static/map/map.json`; это оценка без пробок и происшествий. Движок (`static/js/geo.js`) покрыт тестами на синтетических сетях и на настоящей карте.

**Досье.** Вкладка «Досье»: карточки людей и организаций, с которыми пачка сталкивалась. У карточки есть имя, позывной, короткая строка «кто это», отношение пачки (контакт, союзник, нейтрален, враг, неясно), организация, список персонажей, знакомых лично, последняя встреча (дата и место с карты) и список сведений. Поиск ищет по имени, организации и открытым сведениям, у мастера ещё по заметкам и поправкам. Видимость работает на двух уровнях: карточка открыта всем, только знающим персонажам или скрыта от игроков, и у каждого сведения своя видимость. Игрок получает только то, что открыто его персонажам; заметка мастера и поправка «на самом деле» (для сведений, в которых пачка ошибается) на его устройство не отправляются. При первом запуске из `config/campaign.json` загружаются 57 скрытых карточек с заметками из байбла (раздел 9 и справки по фракциям). Загрузка происходит один раз, потом досье правится только в портале.

**Картинки в досье.** К карточке можно добавить картинку (портрет человека или эмблему организации). Мастер выбирает файл, в браузере подбирает кадр (перетаскивание и масштаб), картинка сжимается до квадрата. Сервер перекодирует её ещё раз в два WebP: 480×480 для карточки (до 90 КБ) и 96×96 для списка (до 10 КБ); метаданные, в том числе координаты съёмки, при этом удаляются. Память ограничена двумя лимитами: общий объём всех картинок (`PORTRAIT_QUOTA_MB`, по умолчанию 40 МБ) и размер загружаемого файла (`PORTRAIT_MAX_UPLOAD_MB`, по умолчанию 8 МБ). Слишком большие по разрешению, повреждённые и не-картинки отклоняются с понятным сообщением. Картинки хранятся в базе и попадают в резервные копии. Адрес картинки содержит случайный токен, который получают только те игроки, кому открыта карточка, и который меняется при замене.

**Раздатки.** Вкладка «Раздатки»: HTML-страницы, которые пачка получила на руки. Мастер загружает файл, указывает дату получения, кому выдана (всей пачке, отдельным персонажам или черновик), комментарий для игроков, место на карте и заметку для себя. Игроки видят только выданное им, получают уведомление в Telegram, на вкладке отмечено число непросмотренных. Раздатка открывается на весь экран, есть переход к дню в календаре и к месту на карте; в хронике раздатки показаны в своём этапе. Файл хранится в базе в сжатом виде (текст сжимается в 5–50 раз) и попадает в резервные копии. Лимиты: `HANDOUT_QUOTA_MB` (общий объём в сжатом виде, по умолчанию 100 МБ) и `HANDOUT_MAX_UPLOAD_MB` (один файл, по умолчанию 15 МБ). HTML открывается в «песочнице» (заголовок `Content-Security-Policy: sandbox`): его скрипты работают, но не видят ни страницу портала, ни вход, ни API, даже если открыть ссылку отдельно. Из-за этого внутри раздатки не работает `localStorage`. Если раздатка умеет масштабироваться (раздатки, которые собирает Claude, содержат для этого небольшой встроенный скрипт), просмотрщик показывает кнопки «−», «+» и «по ширине»: на телефоне лист A4 вписывается целиком и приближается кнопками, щипком или двойным касанием. Остальные HTML открываются как есть.

**Кто свободен.** В форме новой записи под датами показано, кто из выбранных участников занят в эти дни и на это время суток: встречи и дела (развитие и обещания время не занимают), общие события мастера и привычки персонажей. Приглашение без ответа и запись, которой нужна другая дата, дают «возможно занят(а)». Если кто-то занят, ниже предлагаются ближайшие дни, когда свободны все (в пределах 60 дней), и нажатие на день подставляет его в форму. Считается только по тому, что видит сам человек: чужие личные записи и маски мастера для других персонажей не показываются. При правке записи она сама себя не занимает.

**Кнопки в сообщениях бота.** С `TG_WEBHOOK=1` (и `SITE_URL` с https) под приглашением в запись появляются «Принять» и «Отклонить», а мастеру под заявкой на развитие «Подтвердить» и «Отклонить»: ответить можно, не открывая портал. Нажатия приходят на `/api/telegram/webhook` и выполняются теми же правилами, что на портале, от имени нажавшего. Пока webhook включён, `getUpdates` у бота не работает (`python -m app.telegram_bot delete` выключает). Подробнее в `ЗАПУСК.md`, раздел 10.4.

**Личные уведомления.** Бот пишет человеку лично, если тот нажал «Запустить» (приглашения, ответы, развитие, раздатки, общие события). Новые сообщения в обсуждении записи приходят одним уведомлением примерно через `CHAT_NOTIFY_DELAY` секунд (по умолчанию 300) после первого. Если игрок не ответил на приглашение, через `REMIND_DAYS` дней (по умолчанию 2) бот напомнит, потом ещё раз (всего `REMIND_MAX`, по умолчанию 2); `REMIND_DAYS=0` выключает напоминания. Кнопка «Уведомления» вверху портала открывает личные настройки: режим «сразу» или «одной сводкой раз в день», тихие часы, часовой пояс (до выбора действует `DEFAULT_TZ`), пробное сообщение. Уведомления идут через очередь в базе с повторными попытками; её разбирает фоновый планировщик (`SCHEDULER=1`).

**Корзина и история изменений.** В панели мастера, внизу. Всё, что удалено (запись календаря вместе с обсуждением, карточка досье, место, раздатка, этап, таймер и так далее), попадает в корзину и хранится `TRASH_DAYS` дней (по умолчанию 30), оттуда это можно восстановить одной кнопкой или удалить окончательно. Картинка и файл удалённого остаются в базе, но по ссылке не открываются и в лимит не входят; при восстановлении выдаётся новая ссылка. История изменений показывает, кто, когда и что менял, включая действия игроков (создание, правки и удаление записей, ответы на приглашения и другое), хранится `AUDIT_DAYS` дней (по умолчанию 365). У правки можно раскрыть «Что изменилось» (было и стало) и нажать «Откатить»: прежние значения вернутся. Можно отменить добавление, вернуть удалённое, вернуть время в игре. Поиск идёт по названию и имени. Историю одного элемента можно открыть кнопкой «История» в карточке досье или записи. Игроки корзину и журнал не видят. Версии базы ведутся автоматически (`PRAGMA user_version`): при обновлении портал сам приводит старую базу к новой схеме.

**Выгрузка для Obsidian.** В панели мастера кнопка «Сформировать выгрузку» собирает всё содержимое портала в одну заметку Markdown: календарь, хронику с заметками мастера, записи с обсуждениями, этапы, план, таймеры, регулярные события, места на карте, описания районов, раздатки и досье. Это удобная читаемая копия ваших записей в дополнение к резервным копиям базы.

**Маски для плана мастера.** У события плана можно включить маску: игроки увидят на эти дни общее событие с другим текстом, например «Риг позвал всех к себе в ангар», и не станут ничего на них планировать. Настоящее описание на их устройства не попадает. Бот сообщает затронутым игрокам о новой или изменённой маске.

**Видимость этапов.** Игроки видят название этапа с его первого дня. Поле `name` показывается игрокам, поле `gm` только мастеру. Регулярные события с `"vis": "мастер"` игрокам не видны.

**Резервные копии.** `python -m app.backup` кладёт проверенную копию базы в `data/backups` и хранит последние 14. Ежедневная копия в 5 утра:

```
0 5 * * * cd /opt/seattle2075-portal && docker compose exec -T app python -m app.backup
```

Без Docker: `0 5 * * * cd /opt/seattle2075-portal && set -a && . ./.env && set +a && sudo -E -u portal .venv/bin/python -m app.backup`.

Чтобы копии были не только на сервере, поставьте в `.env` `BACKUP_TELEGRAM=1`: каждая копия уйдёт мастеру в личные сообщения от бота (сжатая, до 50 МБ). Можно также забирать папку `data/backups` через `scp` или `rclone` (см. `ЗАПУСК.md`, раздел 13). `python -m app.backup --verify` проверяет копию и показывает, что в ней лежит; `python -m app.backup --restore ФАЙЛ` восстанавливает базу (портал на это время останавливается, прежняя база сохраняется как `before-restore-….db`). Коды возврата: 0 всё хорошо, 1 ошибка, 2 копия сделана, но в Telegram не ушла. Если задан `HEALTHCHECKS_URL`, после каждой копии подаётся «пульс» в healthchecks.io: сервис сам напишет вам, если копия не сделалась или cron перестал работать (`ЗАПУСК.md`, раздел 13).

**Обновление кода.** Замените папки `app/` и `static/`, затем `docker compose up -d --build` или `sudo systemctl restart seattle2075-portal`. Данные в `data/` сохраняются.

## Проверка на своём компьютере

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp config/players.example.toml config/players.toml   # впишите любые числа в telegram_ids
DEV_LOGIN=1 COOKIE_SECURE=0 .venv/bin/uvicorn app.main:app --port 8000
```

Откройте `http://127.0.0.1:8000`: под кнопкой входа появится поле, куда вводится Telegram ID из `players.toml`. Так можно зайти мастером и любым игроком, не настраивая бота. На сервере этот режим выключен.

## Автотесты

Интерфейс (`static/js`) проверяют отдельно: `npm ci && npm run lint && npm test`. ESLint ловит опечатки в именах и запрещённые конструкции (`eval`, `new Function`, `javascript:`), `npm test` запускает тесты чистых функций на `node:test`. Сам портал собирать не нужно: `static/` отдаётся как есть.

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/pytest -m "not browser"      # быстрые проверки, около минуты
.venv/bin/playwright install chromium  # один раз
.venv/bin/pytest -m browser            # проверки в настоящем браузере
```

Тесты идут на отдельной временной базе и на вымышленной кампании из `tests/fixtures/` (все «секреты» в ней начинаются со слова «СЕКРЕТ»), ваши данные они не трогают. Что проверяется: вход и подписи Telegram, права мастера и игрока, что ни один секрет мастера не доходит до игрока, сценарии записей, загрузки картинок и раздаток, отзыв ссылок при сужении доступа, устойчивость к мусору в запросах (любое поле любого запроса заменяется на списки, словари, `null` и огромные числа: ответ должен быть 4xx, не 500), а в браузере ещё и то, что чужой текст не исполняется как код ни на одной странице. Всё это запускается в GitHub Actions на каждый пуш.

## Репозиторий и сборка на GitHub

Настоящий `config/campaign.json` содержит заметки мастера и скрытые карточки досье, поэтому он занесён в `.gitignore` и в репозиторий не попадает. Вместо него лежит пустая заготовка `config/campaign.example.json`. Для нового развёртывания без своих данных скопируйте её: `cp config/campaign.example.json config/campaign.json`. Свой файл кладите на сервер вручную (например, через `scp`), в репозиторий его добавлять не нужно.

Workflow `.github/workflows/ci.yml` на каждый пуш и на каждый pull request в `main` запускает пять заданий:

1. **Запуск приложения**: страница, карта и `/api/state` без входа (должен быть 401) отвечают как надо, файл службы systemd проходит проверку и оценку защищённости.
2. **Автотесты**: `pyflakes` и весь `pytest` без браузера.
3. **Проверки в браузере**: Chromium открывает все разделы с вредными строками в каждом поле.
4. **Docker**: образ собирается, контейнер запускается в усиленном режиме (файловая система только для чтения, без привилегий) до состояния `healthy`, внутри делается резервная копия. Заодно проверяются `Caddyfile` (`caddy validate`), конфиг nginx (`nginx -t`) и оба compose-файла.
5. **Публикация образа**: только для ветки `main` и тегов вида `v1.2.3`, и только если всё выше зелёное. Образ кладётся в GitHub Container Registry: `ghcr.io/moschnopokak/seattle2075_portal_ru` с метками `latest`, хеш коммита и номер версии. В образе нет ни `.env`, ни данных кампании, только код, шрифты и карта.

Выпустить версию: `git tag v1.0.0 && git push origin v1.0.0`. Образ появится с меткой `1.0.0`. Сервер можно обновлять одной командой без сборки на нём (`ЗАПУСК.md`, раздел 14, способ Б).

Раз в неделю Dependabot сам присылает pull request'ы с обновлениями библиотек, базового образа Docker и самих действий GitHub Actions. Каждый из них проходит те же проверки, так что ломающее обновление видно сразу.

Результат виден на вкладке **Actions**. Токен бота и другие секреты для проверок не нужны.

## Внешние обращения страницы

Карта, шрифты и остальная статика лежат на самом сервере. Браузер обращается наружу только за двумя скриптами Telegram (`telegram.org`: вход на сайте и работа внутри Telegram), Telegram требует грузить их именно оттуда. Если Telegram недоступен, страница всё равно открывается, не работает только вход.

## Безопасность

- В `data/secret.key` лежит ключ подписи сессий. Если его сменить, все выйдут из портала.
- Telegram ID надёжнее имени пользователя: имя можно сменить или освободить.
- Выйти из портала можно кнопкой «Выйти» в шапке. Закрыть доступ человеку: удалить его из `players.toml`.

**Что защищает портал на уровне сервера.**
- HTTPS с заголовком HSTS (Caddy или nginx): браузер год ходит на сайт только по `https`.
- Страницу нельзя встроить на чужой сайт (`frame-ancestors`), разрешены только сам портал и веб-версии Telegram.
- Cookie входа с флагами `HttpOnly`, `Secure`, `SameSite=Lax`.
- Раздатки открываются в изолированной «песочнице» браузера: их скрипты не видят ни портал, ни вход.
- Ссылки на раздатки и картинки досье меняются, когда доступ к ним сужается или закрывается.
- Docker: контейнер портала работает с файловой системой только для чтения (пишет лишь в `data/`), без привилегий, с проверкой состояния и ограничением размера журналов. Без Docker: служба systemd запущена в «песочнице» (оценка `systemd-analyze security` около 3.4 из 10, чем меньше, тем лучше).
- Запросы ограничены по размеру на уровне веб-сервера (16 МБ).
- В `index.html` нет ни одного inline-скрипта, стиля или обработчика события (это проверяет тест), поэтому можно включить строгую политику CSP: скрипты только с нашего сервера и из `telegram.org`. Режим задаётся `CSP_MODE`: `report-only` (по умолчанию) только пишет нарушения в журнал строками «CSP: …», `enforce` блокирует. Рекомендуемый порядок: неделю поработать в `report-only`, убедиться, что в журнале нет строк «CSP:», затем поставить `CSP_MODE=enforce` и `docker compose up -d`. Кнопка входа Telegram работает через редирект (`/auth/telegram`), старый способ с JS-обработчиком включается `TG_WIDGET_MODE=callback`.
- Если задан `BOT_TOKEN`, вход без Telegram (`DEV_LOGIN`) не работает, даже если его включили по ошибке.
